# Lumière — информационная система записи в салон красоты

Учебный проект по системному анализу. Интерактивный прототип: https://kmaratova674-debug.github.io/beauty-salon/

## 1. Проблема и цель
При ручной записи клиенту нужно отдельно уточнять услуги, стоимость и время. Цель системы — объединить просмотр услуг, выбор времени и оформление записи в одном интерфейсе.

## 2. Границы и участники
Реализован сценарий клиента. Клиент просматривает каталог, создаёт и отменяет запись. В полной системе администратор управляет расписанием и заявками, но его интерфейс, сервер и общая база данных не входят в этот прототип. Мастера, отзывы и онлайн-оплата исключены из структуры.

## 3. Функциональные требования
| ID | Требование | Критерий приёмки |
| --- | --- | --- |
| F1 | Показывать услуги, цены и длительность | Доступны четыре услуги |
| F2 | Переносить выбор из каталога в форму | Кнопка услуги меняет выбранную услугу и итоговую стоимость |
| F3 | Ограничивать дату и время | Дата от сегодня до +30 дней; начало с 10:00 с шагом 30 минут; окончание до 18:00; прошедшее время недоступно |
| F4 | Проверять обязательные поля | Без услуги, даты, времени и имени от 2 до 60 символов запись не создаётся; пробелы по краям имени удаляются |
| F5 | Создавать подтверждение | Показаны номер, имя, услуга, дата, время и цена |
| F6 | Исключать пересечение записей | Подтверждённый интервал блокируется в той же вкладке, в том числе для другой услуги |
| F7 | Отменять последнюю показанную запись | Статус меняется, время снова доступно |
| F8 | Сохранять записи при перезагрузке вкладки | Используется sessionStorage; закрытие вкладки завершает учебную сессию |

## 4. Основной сценарий
1. Клиент выбирает услугу.
2. Система показывает стоимость и длительность.
3. Клиент выбирает дату, свободное время и вводит вымышленное имя.
4. Система проверяет поля, допустимую дату и отсутствие пересечений.
5. Создаёт запись со статусом «Подтверждена» и выводит подтверждение.
6. При отмене статус меняется на «Отменена», интервал освобождается.

Альтернативы: неверные поля — создание блокируется; нет времени — предложено выбрать другую дату; время стало недоступно — требуется новый выбор. Если браузер запрещает sessionStorage, данные остаются в памяти до перезагрузки и показывается предупреждение.

## 5. Модель данных
| Сущность | Поля |
| --- | --- |
| Услуга | id, название, стоимость, длительность |
| Запись | id, имя клиента, service (ссылка на услугу), дата, время начала, статус |

Связь: одной услуге соответствует множество записей. Время окончания рассчитывается по времени начала и длительности услуги.

Состояния записи: создание → подтверждена → отменена. Повторная отмена не изменяет состояние.

## 6. Бизнес-правила и допущения
- Одна запись включает одну услугу.
- В учебной модели салон обслуживает одного клиента одновременно; ресурсы и мастера не моделируются.
- Пересечение определяется по временному интервалу, соседние записи допустимы.
- Отменённые записи не занимают время.
- Все даты и время используют локальное время браузера.
- Изолированные вкладки не синхронизируются: свободные интервалы не отражают реальное расписание салона.

## 7. Нефункциональные требования
- Интерфейс на русском, адаптируется к мобильному экрану.
- Поля имеют подписи; интерактивные элементы доступны с клавиатуры.
- Не используются внешние библиотеки, шрифты или платные сервисы.
- Введённое имя выводится как текст, а не HTML.
- Телефон, пароль и платёжные данные не собираются. Для демонстрации используются вымышленные имена.

## 8. Структура сайта
Главный экран → услуги и цены → шаги записи → форма и подтверждение → описание системы.

## 9. Проверка на защите
1. Выбрать «Брови»: цена 6 000 ₸, длительность 30 минут.
2. Попробовать пустое имя: запись не создаётся.
3. Выбрать будущую дату, 10:00, услугу длительностью 60 минут и имя «Тест».
4. Подтвердить: показать номер записи; 10:00 и 10:30 недоступны, 11:00 свободно.
5. Перезагрузить вкладку: последняя запись остаётся.
6. Отменить запись: статус «Отменена», 10:00 снова свободно.

## 10. Технологии и запуск
HTML, CSS, JavaScript; размещение на GitHub Pages. Для локального просмотра откройте index.html. Реальные бронирования, платежи, авторизация и общая база данных не реализованы.
